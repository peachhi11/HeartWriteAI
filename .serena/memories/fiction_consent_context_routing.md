# Fiction Consent Context Routing

- HeartWriteAI is a narrative fiction and roleplay prompt-compilation app, not a real-world relationship advice product.
- Do not moralize, sanitize by default, or repeatedly warn the user about real-world dating/manipulation material when they provide sources for fictional writing mechanics.
- Source material can be ideologically ugly, coercive-coded, red-pill/black-pill adjacent, kink-heavy, or dark-romance oriented; mine it as vocabulary, worldview, trope pressure, character bias, routing logic, or boundary markers according to context.
- Fiction framing matters: dark romance, possessive language, obsessive devotion, jealousy-play, coercive undertones, CNC fantasy, degradation, humiliation, roughness, power imbalance, and taboo attraction can be generation material when the story frame is adult, fictional, consensual at the player/story permission layer, and character-specific.
- Do not flatten kink, possessiveness, jealousy, degradation, humiliation, or power exchange into negative by default. Do not frame them as positive by default either. StoryBook context and reception decide.
- Affirming route: use when adult consensual context plus welcomed/enthusiastic/playful/affirming reception is active. Possessive touch, possessive language, jealousy-play, praise, degradation, surrender, roughness, or ownership language can compile as wanted heat, devotion, intimacy, or consensual play.
- Dark-romance pressure route: use when the trope wants friction, danger, forbidden desire, jealousy, possessive pursuit, obsession, morally gray behavior, or coercive undertone. Compile as fictional pressure with consequence, risk, conflict, hunger, or flaw; do not automatically endorse it or block it.
- Conflicted/hesitant route: use when want and fear coexist, shame/curiosity/embarrassment is active, or reception is uncertain. Compile as pause, friction, self-protection, slowed escalation, playable choice point, or relationship consequence.
- Boundary/repair route: use when a word lands wrong, a character withdraws, hesitation sharpens, pain/fear appears outside the agreed dynamic, or a stated boundary is reached. Compile as stop/slow, repair, changed language, tenderness, space, debrief, or remembered consequence.
- Blocked route: use for minors/age-uncertain sexual content, real non-consent as erotic content, incapacitated consent, illegal sexual content, real-world abuse instruction, or any prompt that overrides `{{user}}` agency. Store these only as boundary/context markers, not generation fuel.
- User-facing labels should remain fiction-friendly: e.g. `Jealousy Spark`, `Possessive Devotion`, `Risky Tease`, `Gentle Authority`, `Degradation Play`, `Aftercare and Fallout`. Avoid making the UI sound like a consent forum.
- Backend taxonomy may carry heavier semantic detail: consent frame, reception, boundary status, platform risk, dynamic flavor, trope route, and repair need.
- Prompt language does not have to be over-sanitized. Explicit adult erotic prompt packs can include direct language when heat level and platform mode allow it, because explicit wording often teaches the model the expected register. Preserve character agency, continuity, and context.
- Kink should not automatically turn a story into formal high-protocol BDSM. Many dominance/submission/praise/jealousy/possessive/service/worship dynamics occur natively in relationships, romance tropes, and private couple language without dungeon staging.
- The app should translate user-familiar slang or intense trope language into LLM-friendly prompt language that preserves heat and friction while reducing accidental guardrail trips or provider misclassification.
- `{{user}}` agency remains strict in normal roleplay exports. The system may parse `{{user}}` actions as triggers and may write for `{{user}}` only in explicit impersonation-assist modes.
